## Interaction changes and research

The editor now shows a validated monthly-cost preview as the draft changes, without saving or constructing an amortization schedule. The same lightweight calculation supplies list values and sorting. Invalid financial input removes the stale amount and shows useful guidance. Brief native numeric transitions follow Reduce Motion, and success feedback follows a successful save. A tap in the chart retains an exact year and balance; plot/year bounds prevent out-of-range selection, while vertical scrolling and the exact schedule remain available.

On iPad, one NavigationStack owns a native page-sized editor on iOS 18 and later. Native LabeledContent pairs ordinary-size labels and values across the available width; compact layouts and accessibility sizes retain stacked inputs. Numeric controls preserve a 44-point minimum touch area, clear labels and inline errors. A full-width native keyboard avoids the separate numeric popover covering labels. Section headers and the annual-cost note retain their ideal vertical height. Rotation preserves the unsaved draft, and cancellation leaves the saved estimate intact. These changes use system components rather than additional decoration. Name wraps at compact accessibility sizes without reducing its font. Actual layout bounds keep the focused input above Done when it fits; very short viewports retain native caret scrolling. Starting a scroll dismisses the keyboard with the system API so browsing can continue freely.

Correctable input errors precede their fields and lead directly to correction, keeping the guidance above the focused value when the keyboard appears. Save and unit-conversion failures reveal the input without requiring a duplicate alert acknowledgement; raw values and rejected conversion units remain intact. Each input includes its specific error in a native accessibility hint. Failed validation retains the responder and directly requests the affected field. Successful Save and fieldless modal errors clear focus. The new source removes a scheduling assumption: [Task.yield](https://developer.apple.com/documentation/swift/task/yield()) does not establish completed layout, while Apple’s [FocusState validation example](https://developer.apple.com/documentation/swiftui/focusstate) requests the invalid field directly. This is a bounded source correction, not proof that scheduling caused the earlier keyboard failures. Storage failures and fieldless stale/deleted-record errors retain native alerts. This is a design inference from [Apple’s alert guidance](https://developer.apple.com/design/human-interface-guidelines/alerts), which recommends using task-interrupting alerts sparingly; it is not a diagnosis of native test waits or a measured satisfaction claim.

The studies below inform the design; they do not measure this app's satisfaction, latency or frame rate. System Reduce Motion behavior is source-reviewed; its actual OS setting and physical haptic output have not been tested.

| Primary research | Observed context and app design inference |
| --- | --- |
| [Tuch et al., 2012](https://research.google/pubs/the-role-of-visual-complexity-and-prototypicality-regarding-first-impression-of-websites-working-towards-understanding-aesthetic-judgments/) | Two website-screenshot experiments found low visual complexity and familiar layouts more appealing on first impression. Inference for this app: preserve familiar native controls, one prominent live result and progressive detail. The study did not test iOS apps or repeated mortgage workflows. |
| [Heer and Robertson, 2007](https://idl.cs.washington.edu/files/2007-AnimatedTransitions-InfoVis.pdf) | Controlled statistical-chart transitions aided perception and were preferred; heavy staging increased errors in some tasks. Inference: use brief numeric transitions, leaving direct chart inspection immediate. |
| [Deber et al., 2015](https://www.tactuallabs.com/papers/howMuchFasterIsFastEnoughCHI15.pdf) | Tapping/dragging studies measured perception of latency and latency improvements; desirability benefits remained follow-up work. Inference: calculate a lightweight preview without waiting for Save. App latency and satisfaction have not been measured. |
| [Tversky, Morrison and Bétrancourt, 2002](https://www.tc.columbia.edu/faculty/bt2158/faculty-profile/files/_Morrison_Betrancourt_AnimationCanitfacilitate.pdf) | Reviewed animation for teaching complex systems; animation alone did not ensure learning, and user control could help inspection. Inference: retain selected chart values and avoid decorative or compulsory motion. |
| [Hoggan, Brewster and Johnston, 2008](https://www.dcs.gla.ac.uk/~stephen/papers/CHI2008_eve.pdf) | Tactile feedback improved touchscreen text entry in lab/mobile experiments. Applying feedback to successful Save is a design inference, not a tested mortgage-app benefit. |

[Apple's motion guidance](https://developer.apple.com/design/human-interface-guidelines/motion), [Designing Fluid Interfaces](https://developer.apple.com/videos/play/wwdc2018/803/) and [Swift Charts interactivity guidance](https://developer.apple.com/documentation/charts/visualizing-your-app-s-data) inform the use of system motion preferences, responsive feedback and native chart selection. They do not substitute for testing this app or establish a quantified satisfaction improvement.

The shared scheme runs calculation/persistence and UI targets. UI journeys use unique disposable on-disk stores; Release ignores the debug-only store seam. Field replacement requires an available native raw-string value, sends deletion keys and the replacement in one public typing operation, and asserts exact final raw-string equality within 15 seconds. Explicit empty replacements require an actual empty string; an unavailable value or placeholder cannot pass. Nonempty replacements no longer pause to observe a transient empty state; dedicated empty-price and incomplete-preview journeys retain that coverage. Name uses a native TextField with compact accessibility wrapping; the full bound value remains editable. Editing helpers expose the entire control before touching it, and verify the fresh exact Name value after Done. Largest-text checks retain the focused field and caret above Done and below navigation. A short native gutter drag dismisses both focus and keyboard, reveals the unchanged property price, and can return to Name before saving its exact value. Geometry comparisons allow 0.001 point solely for floating-point edge rounding, well below one physical pixel. Persistent input labels and accessible names remain when numeric placeholders are empty. Native action checks use the foreground app window and fresh screen geometry, keyboard/focus dismissal and editor preservation. Checks allow 15 seconds for share-sheet Copy and 20 seconds for the Save button to disappear; these are test readiness checks, not changes to saving. XCTest now uses an explicit 600-second outer case hang limit after repeated native 60-second event-idle waits exhausted the previous 300-second limit. Field checks retain 15 seconds and Save dismissal retains 20 seconds; the 35-minute hosted job cap is unchanged. This harness relaxation does not establish app responsiveness, and synchronous native operations can overrun waiter allowances. Result bundles and requested attachments remain enabled; diagnostic collection is disabled after an observed collection hang.

The regular accessibility checks now use two complete journeys: detail/schedule and editor/cancellation. All existing audits and annual-cost containment checks remain. The editor check also verifies that Cancel preserves the detail scroll position. The scroll helper stops when the full control is visible, and Done reuses its just-completed existence check before reading fresh geometry and delivering a native touch. Exact empty/replacement values are queried within the editor Form, with the same 15-second assertions; nil, partial and incorrect values still fail. These test-driver changes address observed native snapshot delays while retaining their state and value assertions.

Every inline-recovery check requires the software keyboard, complete error/input containment, exact labels, Done, no modal and foreground state. Direct correction uses [native `typeText`](https://developer.apple.com/documentation/xcuiautomation/xcuielement/typetext%28_%3A%29) without a repair tap, then checks exact text delivery and stale-error removal. Apple's Xcode 27 public API contract requires keyboard focus for this call. A prior one-step Name exception was removed after the app's correction-focus ordering changed; no hardware-keyboard cause is established for the earlier failures. Conversion rollback checks reveal and read the retained unit and amount after direct price correction and Done, before retrying conversion. Price editing does not change those draft fields.

The CI-only [keyboard fixture helper](../scripts/configure-simulator-keyboard.py) verifies that the exact selected simulator is available and shut down before changing preferences. It refuses running DeviceHub or Simulator frontends, preflights both existing preference dictionaries, preserves all unrelated common/device settings, and configures three Boolean false values: legacy common `ConnectHardwareKeyboard`, selected `DevicePreferences[UUID].ConnectHardwareKeyboard`, and DeviceHub global `alwaysSimulateHardwareKeyboard`. Native full-domain export/import and exact typed readback are required. Malformed, unreadable, concurrent-looking or unsuccessful operations abort before boot/tests. Imports across domains are not atomic; exclusive disposable-runner ownership is required, and a partial failure aborts that fixture. Owner preferences were not accessed. The [14 helper tests](../scripts/test_configure_simulator_keyboard.py) cover these failure/preservation boundaries; the native dummy-domain proof verifies actual import/export, types, preservation and idempotence with runtime guards stubbed.

This three-location configuration follows the current maintainer’s [preference compilation](https://github.com/appium/appium-ios/blob/main/packages/simulator/lib/extensions/settings.ts#L476-L483) and [legacy/domain translation](https://github.com/appium/appium-ios/blob/main/packages/simulator/lib/extensions/settings.ts#L350-L407). The workflow follows its [normal startup order](https://github.com/appium/appium-ios/blob/main/packages/simulator/lib/extensions/ui-client.ts#L75-L120): preferences, active-Xcode frontend launch, then selected-device boot. The active Xcode DeviceHub bundle path and native bundle identifier are verified before `open -Fn`; a path-scoped PID must appear within 30 seconds. Eight private dummy-frontend checks cover readiness, missing/malformed/wrong bundle identity, launch failure, process-discovery errors and expiry, without launching an owner frontend. PID discovery proves only that a bundle process exists; window readiness, selected-screen presentation and effective keyboard behavior remain native-test gates. The earlier [headless path](https://github.com/appium/appium-ios/blob/main/packages/simulator/lib/extensions/ui-client.ts#L173-L218) ignored UI options and did not establish the earlier failures’ cause. Appium is not an app or test dependency. Actual frontend state is logged before and after native testing. The software-keyboard absence observer uses 15 seconds with the same predicate and single Done action; Name correction now has its own regular and largest-text journeys; each numeric zero/empty/corrected-value sequence retains its original checks. The outer harness limit is separately stated above.

Inline-error queries use the observed native StaticText within the Form for visibility and stale-error removal. The original log identifies that same error as StaticText. Both typed replacements retain fresh labels, frames, viewport checks, hittability, keyboard requirements and correction actions.
